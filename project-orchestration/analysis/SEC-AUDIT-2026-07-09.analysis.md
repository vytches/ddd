# SEC-AUDIT-2026-07-09 — Security & Consistency Pattern Audit

```yaml
artifact: SEC-AUDIT-2026-07-09.analysis.md
date: 2026-07-09
scope: all 19 packages, src/ only (tests/examples excluded)
method:
  6 parallel audit dimensions (error handling & info leakage, deserialization &
  input handling, global mutable state & registries, IDs/randomness/time,
  internal diagnostics & data exposure, resilience & NestJS), top findings
  re-verified in source by hand
status: findings triaged into tasks (see Mapping section)
```

Goal: find patterns in the library that produce undesirable behavior in
production consumer applications — security, consistency, predictability.
Constraints honored: `any` types are intentional; dependency-free is by design;
the internal logger is deliberately internal-only.

## Findings

### Critical / High

- **SA-C1** — `TranslationError` stores the full source domain/external model as
  a public enumerable field (`packages/acl/src/acl-errors.ts:54`, populated by
  `packages/acl/src/base-translator.ts:21-30,44-51`). The error hierarchy has no
  `toJSON()`, so `JSON.stringify(err)` (any JSON logger, any naive exception
  filter) serializes the complete model — a live PII leakage vector on exactly
  the path that fires on cross-context schema drift. Verified by reproduction:
  object data survives, while `message` (non-enumerable) is dropped.
- **SA-C2** — `EntityId.create()` generates its UUID with a hand-rolled
  `Math.random()` template
  (`packages/contracts/src/domain/entity-id.implementation.ts:145-153`). This is
  the documented primary ID factory (JSDoc examples in `aggregate-root.ts` point
  at it). Predictable identifiers (enumeration/IDOR risk when exposed) and
  collision-prone at scale. The same package already uses
  `globalThis.crypto.randomUUID()` correctly
  (`contracts/src/events/domain-event-utils.ts:15-17`), and
  `packages/value-objects/src/id.value-object.ts:77-79` overrides `create()`
  correctly — the fix is a one-line alignment.
- **SA-H1** — CQRS `LoggingMiddleware` is installed **by default**
  (`enhanced-command-bus.ts:153-155`, `enhanced-query-bus.ts:252-254`; gate is
  `enableMetrics !== false`) and writes to raw `console`, bypassing
  `configureDiagnostics` entirely. `level: 'silent'` does not silence it; the
  only opt-out is the non-obvious `enableMetrics: false`.
- **SA-H2** — Same middleware logs `${error}` on failure
  (`packages/cqrs/src/middleware/logging.middleware.ts:36`). Validation/domain
  error messages conventionally embed the offending input value → indirect
  PII-to-console vector, on by default.
- **SA-H3** — `jitter: false` is hardcoded in both buses' retry wiring
  (`enhanced-command-bus.ts:204`, `enhanced-query-bus.ts:309`) and the
  `resilience.retry` options expose no `jitter` field. Fleet-wide synchronized
  retry waves (thundering herd) against a recovering downstream. `RetryPolicy`'s
  own default is `jitter: true` — bypassed at the one integration point that
  matters.
- **SA-H4** — `ServiceLocator` (+ `VytchesDDD` wrapper) is a process-global
  singleton whose `configure()`/`configureContext()` silently overwrite the
  active container (`packages/di/src/service-locator.ts:84-122`).
  Re-bootstrap/hot-reload/second module silently swaps DI for the whole process.
  _Requires a design decision (collision semantics) — see Non-task items._
- **SA-H5** — `PolicyViolation.toJSON()` explicitly includes `stack`
  (`packages/policies/src/core/models/policy-violation.ts:131`) in a method
  documented for serialization — server paths/call structure leak wherever it
  crosses a boundary.
- **SA-H6** — No `toJSON()` anywhere in the `BaseError`/`IDomainError` hierarchy
  (`packages/domain-primitives/src/errors/`): `JSON.stringify` drops `message`
  (non-enumerable) but keeps `data` (enumerable). Broken message-less logs
  today; automatic leak inheritance for any future factory that attaches richer
  `data`.

### Medium

- **SA-M1** — The `ddd-002 no-throw-in-domain` lint gate has always been a no-op
  in the repo's actual wiring: `isDomainFile()`
  (`tools/ddd-lint/src/rules/no-throw-in-domain.ts:70-87`) requires a leading
  slash (`/aggregates/`), but `npm run ddd:lint` scans with root `packages`,
  producing relative paths (`aggregates/src/...`) that never match. 0 findings
  via the wired script vs 100+ when scanned from repo root.
- **SA-M2** — `@CircuitBreaker`/`@Bulkhead`/`@Retry`/`@Resilience` decorators
  build the policy once at decoration time
  (`packages/resilience/src/decorators/resilience-decorators.ts:51,143-167`) —
  breaker/bulkhead state is shared per-class, not per-instance. Two instances
  (e.g. request-scoped providers, clients of different downstreams) trip each
  other's breaker.
- **SA-M3** — Circuit breaker HALF_OPEN admits unlimited concurrent calls
  (`packages/resilience/src/patterns/circuit-breaker.ts:108-113`; `execute()`
  never gates probes) — full traffic floods a recovering dependency instead of a
  single canary.
- **SA-M4** — `BusinessRuleValidatorAdapter.isSatisfiedBy` converts any thrown
  exception to `false` with zero logging
  (`packages/policies/src/adapters/specification-adapters.ts:32`) — a real bug
  is indistinguishable from a legitimate business refusal.
- **SA-M5** — `UnifiedEventBus.autoRegisterHandlers()` swallows all errors in a
  bare catch with no diagnostic
  (`packages/events/src/unified-event-bus.ts:120-143`). _Already covered by
  VF-025 (F-M3/F-H11 area); confirmed by this audit._
- **SA-M6** — `executeHandlers` rethrows only `errors[0]` when multiple handlers
  fail (`unified-event-bus.ts:438-465`). _Already covered by VF-025 AC "fan-out
  error aggregation"; confirmed by this audit._
- **SA-M7** — Unknown `eventName` during `loadFromHistory()`/`handleEvent()` is
  silently skipped (`packages/aggregates/src/core/aggregate-root.ts:268-296`) —
  silent data loss on corrupted/renamed replay streams. Same code path as
  VF-023's F-M2 (apply-side missing handler); replay side must be covered
  explicitly.
- **SA-M8** — No injectable Clock in production code: `new Date()` hardcoded in
  `domain-event.ts:47`, `aggregate-root.ts:243`, capabilities, policies,
  projections, circuit-breaker; a Clock abstraction exists only in the testing
  package. Nondeterministic replay timestamps, no consumer injection point.
  _Architectural decision, not a bugfix — see Non-task items._
- **SA-M9** — Optimistic concurrency contract gap: `IEventPersistenceHandler`
  (`packages/contracts/src/events/event-persistence-handler.interface.ts:9-20`)
  documents no atomicity/compare-and-set requirement, while
  `BaseRepository.save` (`packages/repositories/src/base-repository.ts:41-72`)
  does non-atomic check-then-act — two concurrent saves can both pass the
  version check (lost update) unless the consumer's handler is atomic on its own
  initiative.
- **SA-M10** — `DIDomainServiceMetadataRegistry` is fully static with silent
  last-write-wins on `serviceId`
  (`packages/domain-services/src/di-types.ts:140-147`). _Part of the registry
  collision-semantics decision — see Non-task items._
- **SA-M11** — `globalPolicyEventBus` is a module-level singleton exported from
  the public barrel (`packages/policies/src/events/policy-event-bus.ts:309`,
  `packages/policies/src/index.ts:116`) — shared process-global fan-out with no
  tenant/context partitioning; per-request subscribers hit the 100-handler cap.
- **SA-M12** — `RetryPolicy.execute()` never disposes forked attempt contexts
  (`packages/resilience/src/patterns/retry.ts:39-58`), unlike
  circuit-breaker/timeout which dispose in `finally` (VB-004 D-4). Abort
  listeners accumulate when a `ResilienceContext` is reused via
  `contextProvider`.

### Low

- **SA-L1** — Weak `Date.now()+Math.random()` correlation/execution IDs, 4
  near-identical copies: `policy-event-bus.ts:305`,
  `event-driven-policy.ts:290`, `policy-evaluation-event.ts:145`,
  `packages/aggregates/src/capabilities/audit-capability.ts:162` — should call
  `LibUtils.getUUID()` like the rest of the library.
- **SA-L2** — Log injection: `outbox-processor.ts:463-465` interpolates
  `error?.message` with no control-character sanitization.
- **SA-L3** — No ES2022 `cause:` chaining anywhere in the repo; rethrow sites
  keep only the message string (production impact mainly in
  `acl/src/base-translator.ts`).
- **SA-L4** — Inconsistent registry duplicate semantics: `PolicyRegistry` and
  `RulesRegistry` throw on duplicates; ACL/transformer/projection/command/query
  registries silently overwrite (enhanced buses document last-write-wins). _Part
  of the collision-semantics decision — see Non-task items._
- **SA-L5** — `RetryPolicy` retries **all** errors when no `retryableErrors`
  predicate is configured (`retry.ts:66-72`) — non-idempotency footgun for
  direct consumers (the CQRS buses already made retry opt-in, REL-009).

### Verified sound (no action)

Integration-event deserialization (1 MB cap, `__proto__` sanitization, no
type-string dispatch — REL-007); aggregate event arrays (copies, `maxEvents`
guard); event-bus caps and unsubscribe; outbox timer/`allSettled` hardening;
nestjs package post F-C4/VB-003 (lifecycle, WeakMap ledger, complete `@Inject`);
CQRS retry opt-in (REL-009); `internalLogger` call-site discipline (no payloads
anywhere); no `eval`/`new Function`; no deep-merge/clone utility to carry
pollution; validation email regex linear (no ReDoS); `Result<T,E>`
single-sourced and consistent. The env-var-based deprecation suppress in
value-objects is a conscious completed decision (VS-008) — not re-flagged.

## Non-task items (require a design decision first)

1. **Registry/DI collision & reconfiguration semantics** (SA-H4, SA-M10, SA-L4):
   what is an error vs a conscious override across ServiceLocator
   re-`configure()`, static metadata registries, and string-keyed registries.
   One consistent policy (throw / warn / explicit `overwrite: true`) should be
   decided via `/analyze-ddd` before implementation.
2. **Injectable Clock** (SA-M8): optional clock parameter/context for
   event/aggregate timestamps — an API design change touching many packages;
   evaluate separately from bugfixes.
